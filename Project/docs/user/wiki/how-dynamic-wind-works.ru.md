# Как работает Dynamic Wind {#how-dynamic-wind-works}

Dynamic Wind создаёт процедурное движение костей для скелетной Nanite-растительности. Скелет определяет, где растение может изгибаться, группы ветра задают реакцию, а GPU рассчитывает transforms для рендеринга. Этот workflow не требует animation clips, Animation Blueprint и Physics Asset.

Dynamic Wind имеет статус Experimental. Настройка проекта описана в [Подготовке Unreal Engine](../workflows/prepare-unreal.md).

## От ассета к движущемуся растению {#pipeline}

На входе нужен Skeletal Mesh с Skeleton Asset, reference pose и skin weights или скелетными креплениями Assembly. Unreal хранит метаданные ветра как **Dynamic Wind Skeletal Data** в Asset User Data mesh. При импорте метаданных importer сопоставляет имена костей, назначает группы симуляции и строит данные цепочек.

Компонент с transform provider Dynamic Wind регистрирует скелет в системе ветра мира. Каждый кадр GPU compute shader рассчитывает движение костей по reference pose, времени и параметрам ветра. Nanite использует полученные transforms для движения геометрии.

SpeedAssembly передаёт mesh и скелет через USDA, а метаданные ветра через отдельный `*_DynamicWind.json`. JSON содержит назначение костей в группы и настройки реакции. В нём нет animation keyframes, и он не заменяет скелет или skin weights.

## Как читается скелет {#skeleton}

Плагин читает родителей костей, позиции pivot и rotations. Он не распознаёт ствол по форме или ветку по имени. Это определяют назначение групп и флаг **Is Trunk?**.

JSON importer сопоставляет имена с reference skeleton Skeletal Mesh. Во время игры provider читает позиции и rotations из назначенного **Skeleton Asset**. Данные ветра предполагают одинаковые кости, порядок и reference pose у обоих. Skeleton с подходящими именами, но другими rotations костей может давать неправильный ветер, даже если mesh без анимации выглядит корректно.

### Оси костей и pivot {#bone-axes-and-pivots}

Для движения веток шейдер считает **локальную ось +X** кости в reference pose её направлением вперёд. Расчёт следует этой оси, даже когда она не направлена вдоль физического сегмента ветки. Это относится и к конечным костям без детей.

Pivot определяют, где происходит изгиб. Сегменты костей, топология mesh и привязки вершин определяют получаемую кривизну. Несколько костей с одним pivot или вся крона с весами на root не дадут изгибов отдельных участков.

!!! warning "Точно вертикальные оси веток"

    Шейдер веток строит ось через векторное произведение направления кости и Unreal +Z. При точно параллельном или противоположном направлении эта ось не определена. Здесь важна ось +X в reference pose, которая может отличаться от линии между joints. SpeedAssembly исправляет этот случай при скелетном экспорте SpeedTree. Для внешнего rig исходные оси остаются без изменений.

### Границы групп задают цепочки {#chains-come-from-group-boundaries}

Кость входит в цепочку, построенную обходом родителей с той же группой симуляции. Смена группы начинает новую цепочку. Одну группу можно использовать на многих отдельных ветках, если их родители принадлежат другой группе.

Расчёт цепочки предполагает линейный путь внутри одной группы. Если у родителя есть два ребёнка из той же группы, importer объединяет оба пути под одним началом цепочки. Количество костей и градиент influence больше не описывают каждую ветку независимо. Другая группа на одной из выходящих веток даёт ей отдельное начало цепочки. SpeedAssembly отклоняет такое неоднозначное разветвление при экспорте Wind JSON внешнего скелета.

Имена костей сопоставляются **после импорта в Unreal**. Importer может переименовать их, например `Bone.001` в `Bone_001`. Имена JSON без совпадений оставляют кости без нужной группы. Импорт данных ветра в Unreal не останавливается из-за этой ошибки. Если совпал только root, весь объект может жёстко двигаться вместе с ним.

## Что означают настройки реакции {#response-settings}

Группы симуляции задают общую реакцию на ветер для частей растения. Они независимы от материалов, секций mesh, skin weights и определений элементов для инстансинга.

| Настройка | Действие |
| --- | --- |
| **Influence** | Масштабирует собственный изгиб и скручивание кости, не относящейся к стволу. Не меняет skin weights вершин. |
| **Use Dual Influence** | Заменяет одно значение Influence градиентом от **Min Influence** в начале цепочки до **Max Influence** в её конце. |
| **Shift Top** | Смещает большую часть градиента к концу цепочки. Градиент следует индексу кости в цепочке, а не физическому расстоянию. |
| **Is Trunk?** | Выбирает специальный расчёт раскачивания ствола вместо движения веток. Расчёт ствола не использует градиент Influence группы. |
| **Gust Attenuation** | Уменьшает движение ствола по всему ассету. При `1` подавляет собственный поворот ствола от ветра. Это не общая настройка силы движения веток. |
| **Is Ground Cover** | Убирает финальное ослабление поворота веток по высоте, чтобы низкие растения реагировали у земли. Не заменяет расчёт ствола, зависящий от высоты. |

Кость вне группы ствола с нулевым Influence не имеет собственного поворота от ветра, но наследует движение родителей. Поэтому итоговое движение участка зависит от всего пути предков и привязок.

Индексы групп также влияют на смешивание текстурного шума в шейдере. Добавление групп может менять рисунок движения даже при одинаковых значениях Influence.

## Как рассчитывается анимация {#animation}

Расчёт веток объединяет движущийся текстурный шум, волны порывов, изгиб по ветру, скручивание вокруг оси кости вперёд и вертикальное покачивание. Реакция корректируется по высоте кости, направлению относительно ветра, данным длины цепочки и настройкам группы. Ствол использует отдельный, более медленный расчёт раскачивания.

Для каждой выходной кости шейдер проходит до root и накапливает rotations предков и смещения pivot. Поэтому ветка следует за стволом и добавляет собственное движение. Это процедурная модель движения. Она не рассчитывает жёсткость древесины, массу, коллизии и контакт между ветками через физику.

### Общая анимация инстансов {#shared-animation-across-instances}

Dynamic Wind объединяет совместимые скелеты в batches и рассчитывает **восемь вариантов направления** с шагом 45 градусов вокруг вертикальной оси Unreal. Каждый инстанс выбирает вариант по своему world yaw, округлённому до ближайшего сектора.

Копии в одном batch и секторе направления используют общее движение костей. Стандартный workflow не запускает отдельную симуляцию и не создаёт отдельную фазу для каждого дерева. Разный rotation при размещении меняет выбранный сектор, но одинаковые копии всё равно могут двигаться вместе.

Буфер transforms хранит текущее и предыдущее состояние костей для рендеринга движения. Это удваивает объём хранения transforms, а не количество симуляций ветра.

### Глобальные настройки ветра {#global-wind-controls}

**Dynamic Wind Subsystem** мира получает параметры через **Update Wind Parameters**, доступный в Blueprint. Контроллер ветра проекта передаёт направление, скорость, амплитуду и необязательную текстуру ветра. Этот метод описан в [API subsystem от Epic](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Plugins/DynamicWind/UDynamicWindSubsystem).

- **Wind Speed** влияет и на скорость движения во времени, и на его силу. Это управляющее значение шейдера, а не откалиброванная скорость ветра в метрах в секунду.
- **Wind Amplitude** масштабирует повороты от обычного ветра.
- **Wind Texture** задаёт шум для движения веток. Если текстуры нет, provider использует белую текстуру. Движение остаётся, но без вариаций от этой текстуры.

Стандартный шейдер использует время и позиции относительно скелета. Он не читает поле ветра в world space для каждого размещённого инстанса.

## Что нужно во время игры {#requirements}

Работа ветра зависит от нескольких связанных систем:

- Настройки рендеринга проекта и плагины обеспечивают Nanite foliage и Dynamic Wind subsystem. Настройка описана в [Подготовке Unreal Engine](../workflows/prepare-unreal.md).
- Скелетный ассет задаёт иерархию, pivot, оси +X, привязки и совпадающие reference pose mesh и Skeleton.
- Метаданные ветра принадлежат **Skeletal Mesh, используемому компонентом во время игры**. Импорт JSON на другой mesh не настраивает этот.
- **Instanced Skinned Mesh Component** использует transform provider **Dynamic Wind Data**. Он независим от Dynamic Wind Skeletal Data самого mesh. Static Mesh instancer не получает скелетную анимацию ветра из JSON.
- Dynamic Wind Subsystem мира передаёт настройки ветра. Console overrides могут иметь приоритет над speed и amplitude контроллера.

Действие Blueprint в редакторе **Import Dynamic Wind Skeletal Data from File** загружает JSON на целевой Skeletal Mesh и строит кеш данных цепочек. После изменения имён костей, иерархии или назначения групп этот кеш устаревает до повторного импорта метаданных. [Epic описывает действие импорта](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/DynamicWind/ImportDynamicWindSkeletalDatafro-).

## Практические ограничения {#limits}

**Видимую деформацию определяет геометрия.** Основной skinned mesh может изгибаться там, где это позволяют кости, веса и топология. В этом workflow скелетные Nanite Assembly Parts жёстко движутся через свои крепления и не изгибаются внутри. Отдельные элементы позволяют разделить движение креплений, но требуют больше transforms во время игры. Подробнее в [Выборе геометрии для инстансинга](choosing-assembly-parts.md#choose-boundaries-by-movement).

**Движение на GPU не обновляет физический rig на CPU.** Dynamic Wind Data работает только как GPU transform provider. Отрисованная деформация не переносится автоматически на коллизии, тела Physics Asset и запросы sockets из gameplay. У этих систем свои способы обновления движения.

**Анимация может остановиться раньше рендеринга.** У instanced skinned компонентов есть порог **Animation Min Screen Size**. `0` использует глобальный порог рендерера, отрицательное значение компонента отключает отсечение анимации. Поэтому видимое растение вдали может перестать анимироваться без ошибки в ассете.

**Culling зависит от bounds mesh.** Provider Dynamic Wind не передаёт отдельные bounds для анимации. Ветки, выходящие при движении за bounds mesh, могут исчезать у краёв кадра.

**Общий Skeleton Asset означает общую регистрацию ветра.** Mesh с одним Skeleton могут использовать одни данные костей ветра во время игры. Отдельные Skeleton Asset изолируют варианты с разными метаданными ветра.

**Бюджеты костей и Assembly независимы.** Нагрузка ветра зависит от batches скелетов, трансформируемых костей, восьми вариантов направления и глубины предков. Рендеринг также обрабатывает размещённую геометрию и Assembly Parts. Увеличение `r.Nanite.MaxVisibleAssemblyParts` не расширяет буфер костей ветра и не упрощает расчёт ветра. Универсального безопасного количества деревьев на уровне нет.

## Консольные команды и переменные {#console-reference}

Следующие переменные управляют созданием subsystem, переопределениями ветра и поведением шейдера. Значения по умолчанию взяты из проверенных исходников UE 5.8. Настройки проекта могут их переопределять.

### Переменные Dynamic Wind {#dynamic-wind-variables}

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DynamicWind.Enable` | `1` | Управляет созданием subsystem мира при запуске. Во время игры доступна только для чтения. |
| `DynamicWind.OverrideSpeed` | `-1` | Переопределяет Wind Speed при значениях `0` и выше. Любое отрицательное значение возвращает управление переданным параметрам ветра. |
| `DynamicWind.OverrideAmplitude` | `-1` | Переопределяет Wind Amplitude при значениях `0` и выше. Отрицательное значение возвращает управление после того, как смешиваемое значение override станет отрицательным. |
| `DynamicWind.OverrideRateOfChange` | `0.5` | Скорость в секунду, с которой amplitude override приближается к целевому значению. Это не частота движения костей и не общая настройка интерполяции контроллера. |
| `DynamicWind.UseSine` | `0` | Заменяет обычный ветер простым поворотом по синусоиде. Полезна для проверки связи рендеринга с provider. Обходит обычные группы, influence и поведение веток. |
| `DynamicWind.PreferAsyncCompute` | `0` | Запрашивает async compute, если GPU эффективно его поддерживает. |

В режиме sine поворот зависит от скорости и времени и не использует Wind Amplitude. Успешная проверка с sine не доказывает правильное сопоставление групп или корректную деформацию от обычного ветра.

### Дополнительная диагностика {#related-diagnostics}

| Команда или переменная | Действие |
| --- | --- |
| `r.Skinning.TransformProviders` | Глобальное включение transform providers, по умолчанию `1`. Отключение влияет и на providers вне Dynamic Wind. |
| `r.Skinning.DefaultAnimationMinScreenSize` | Глобальный порог отсечения анимации, по умолчанию `0.1`. Используется при значении `0` у компонента. Объясняет, почему видимые инстансы вдали могут перестать двигаться. |
| `r.InstancedSkinnedMeshes.DebugDraw` | Включает debug drawing instanced skinned mesh при `1` и отключает при `0` в сборках с поддержкой этой отладки. |
| `stat GPU` | Показывает GPU timings, включая работу DynamicWind, в сборках с доступной GPU-статистикой. |
| `NaniteStats` | Показывает потребность в transforms Assembly, а не количество костей Dynamic Wind. Значение счётчика описано в [Выборе геометрии для инстансинга](choosing-assembly-parts.md#check-the-transform-demand). |
| `r.Nanite.MaxVisibleAssemblyParts` | Вместимость буфера transforms Assembly, по умолчанию `262144`. При плотном размещении нехватка буфера может приводить к исчезновению элементов независимо от корректности ветра. |

## Откуда берутся проблемы движения {#diagnostics}

Разные ошибки возникают на разных этапах:

| Этап | Результат несоответствия |
| --- | --- |
| Привязка mesh | Неверные веса или pivot двигают не тот участок или мешают изгибу отдельных участков независимо от метаданных ветра. |
| Имена и reference pose | Имена JSON без совпадений теряют назначение групп. Другие rotations Skeleton Asset меняют оси вперёд, используемые во время игры. |
| Компонент во время игры | Данные ветра на другом mesh или компонент без wind provider не настраивают отображаемый ассет. Поэтому прямое размещение и PCG могут давать разный результат, если подключены по-разному. |
| Настройки ветра | Speed и amplitude overrides имеют приоритет над значениями контроллера. Sine обходит обычную реакцию групп и не подтверждает корректную работу обычного ветра. |
| Реакция групп | Разветвления внутри одной группы искажают данные цепочек. Нулевой локальный Influence сохраняет движение предков, а группы ствола используют отдельный расчёт. |
| Рендеринг | Порог screen size останавливает анимацию вдали. Малые bounds могут отсекать движущиеся ветки. Нехватка буфера Assembly может скрывать элементы. Эти симптомы не означают одну и ту же причину. |
