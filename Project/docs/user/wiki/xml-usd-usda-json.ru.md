# XML, USD, USDA и JSON {#xml-usd-usda-and-json}

В этом workflow дерево проходит через несколько файлов. Каждый хранит свою часть данных.

## XML хранит исходные данные SpeedTree {#xml-carries-the-speedtree-source}

XML расшифровывается как *Extensible Markup Language*. Это текстовый формат для структурированных данных с именованными тегами. Программы используют его для настроек, документов и обмена данными. Значение тегов определяет программа, которая их записывает и читает.

Экспорт **Raw XML** из SpeedTree содержит геометрию дерева, скелет, информацию о материалах и размещение инстансов элементов. SpeedAssembly читает эту структуру, чтобы восстановить дерево и его элементы для повторного использования. Для дальнейшей работы сохраняйте исходный проект SpeedTree. XML нужен для передачи данных.

## USD описывает 3D-сцену {#usd-describes-a-3d-scene}

USD расшифровывается как *Universal Scene Description*. Это разработанная Pixar система описания и сборки 3D-сцен. Она может хранить mesh, материалы, скелеты, transforms и инстансы со ссылками на другие ассеты. Художники работают с USD при обмене данными между DCC, в кинопроизводстве и при сборке сцен.

SpeedAssembly использует USD для описания дерева и размещения инстансов веток и листьев. Такая структура подходит для импорта Nanite Assembly в Unreal.

## USDA позволяет читать USD как текст {#usda-is-usd-you-can-read}

**A** означает *ASCII*. `.usda` является текстовым форматом USD, `.usdc` бинарным, а `.usd` может содержать любой из них. USDA использует ту же модель сцены. Текстовый формат не превращает дерево в один общий mesh.

SpeedAssembly записывает `.usda`, чтобы результат можно было проверить в текстовом редакторе. Если нужно разобраться с импортом, геометрия, привязки скелета, инстансы и данные для Unreal доступны напрямую.

## JSON хранит настройки ветра {#json-carries-the-wind-settings}

JSON расшифровывается как *JavaScript Object Notation*. Несмотря на название, с ним работают многие приложения и языки. Он хранит именованные значения и списки в виде текста, обычно для настроек и обмена данными.

Здесь `*_DynamicWind.json` передаёт Unreal назначение костей в группы и настройки реакции на ветер. Геометрия и скелет остаются в USDA. В JSON нет animation keyframes. Dynamic Wind в Unreal генерирует движение во время игры.

Полный порядок передачи ассетов описан в [Конвертации в SpeedAssembly](../workflows/basic-conversion.md). Подробности ветра см. в [Как работает Dynamic Wind](how-dynamic-wind-works.md).
